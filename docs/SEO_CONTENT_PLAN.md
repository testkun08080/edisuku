# エディスク オーガニック流入拡大 企画書

マネタイズ前フェーズの目標：**検索ヒット数と知名度を上げる**。
そのために (1) 現フロントエンドの技術的な欠落、(2) ユーザーが実際に知りたい情報とその企画・構成、の 2 軸で整理する。

---

## 1. 前提：現状のフロントエンド棚卸し

`apps/web` の実装を確認した結果、ページは以下の 5 種類のみ。

| パス | 役割 | レンダリング |
|---|---|---|
| `/` | ランディング（Hero / 特徴 / OSS 訴求） | 静的 |
| `/screener` | 企業一覧・フィルタ・テーブル | クライアント側フェッチ（`"use client"`） |
| `/screener/analyze/:secCode` | 企業別 財務分析（サマリー/指標/大株主/PL/BS/CF） | クライアント側フェッチ（`"use client"`） |
| `/contact` | 問い合わせ（Google フォーム埋め込み） | 静的 |
| `/privacy` | プライバシーポリシー | 静的 |

企業ごとの分析ページは EDINET 収録企業数分（数千社規模）だけ URL が存在しうる、**最大の資産**。ここが弱いことが最大の機会損失になっている。

---

## 2. 足りないもの（技術的課題）

優先度順に「致命的（インデックスを阻害している）」「重要（機会損失）」「あると良い」で分類する。

### 致命的：今すぐ直すべきインデックス阻害要因

1. **canonical タグが全ページ同一**
   `pages/+Head.tsx` の `<link rel="canonical" href={siteUrl} />` はトップページ URL 固定で、`/screener/analyze/:secCode` を含む全ページに出力される。これは Google に対して「このページの正はトップページです」と申告しているのと同じで、企業分析ページが実質的にインデックスされない・されても正規化されて弾かれる原因になりうる。企業数分のページを潰している最大の技術的損失。

2. **サイトマップに動的ページが載っていない**
   `server/sitemap.ts` は `/`, `/screener`, `/contact`, `/privacy` の 4 つの静的パスしか出力しない。数千社ある `/screener/analyze/:secCode` が一切含まれておらず、クロール発見の起点がない。

3. **企業分析ページがクライアント側フェッチのみ（メタ情報が空）**
   `<title>` は `company` 取得後に `config({ title: ... })` で書き換えているが、初期 HTML（SSR/クロール直後）には企業名は入らず、`meta description` も全ページ共通の一般文（`SITE_OG_DESCRIPTION`）のまま。企業ごとの固有情報が検索結果のスニペットに出ないため、クリック率も検索エンジンの評価も伸びない。
   同様に `/screener` の一覧・テーブルもクライアント側フェッチで、初期表示はスケルトンのみ。

4. **構造化データが企業単位で存在しない**
   JSON-LD は `WebApplication` がサイト全体に 1 つあるだけ。企業ごとの `FinancialProduct` / `Dataset` / `Article` 相当の構造化データがなく、リッチリザルトの機会を逃している。

### 重要：機会損失（実装すれば伸びる）

5. **企業ページの OGP 画像が全社共通**
   SNS でシェアされても「エディスク」の汎用画像しか出ず、企業名・主要指標が見えない。SNS 経由の拡散力を落としている。

6. **用語解説コンテンツが存在しない**
   ROE・PBR・PER・自己資本比率・Piotroski F-Score・ROIC など、アプリ内で既に計算・表示している指標について、「〇〇とは」に答えるページが 1 つもない。これは検索ボリュームが大きく、かつアプリの機能と自然に内部リンクできる領域。

7. **ランキング・比較の集約ページがない**
   `PresetScreeners`（ROE が高い／堅実な企業／成長中）のようなフィルタ条件は存在するのに、それを固定 URL 化した「配当利回りランキング」「自己資本比率ランキング」のような、検索意図に直接刺さる静的入口ページがない。

8. **ハウツー・比較コンテンツがない**
   「EDINETとは」「有価証券報告書の読み方」「無料の財務スクリーナー比較」のような、ツールを知らない人が検索するトップファネル記事がゼロ。今は「エディスクを知っている人」しか辿り着けない導線になっている。

9. **FAQ ページがない**
   よくある質問＋ `FAQPage` 構造化データは実装コストが低く検索面積を稼ぎやすいが未着手。

10. **更新情報・鮮度を示すページがない**
    EDINET は日々新しい提出があるはずだが、「本日/今週提出された有報一覧」のような更新系ページがなく、再訪動機・クロール頻度向上・鮮度シグナルを作れていない。

### あると良い：信頼性・拡張性

11. **About / 運営者情報ページがない**
    金融データを扱うサイトとして、運営者・データの正確性方針・OSS である背景を説明するページ（E-E-A-T 対策）がない。`README.md` の情報が Web 上に露出していない。

12. **パンくずリスト（内部リンク構造）がない**
    企業ページ ⇔ 業種ページ ⇔ 用語ページ ⇔ ランキングページを繋ぐ導線が皆無で、クロールの回遊性が低い。

## 3. ユーザーが知りたい情報の整理（検索意図の分類）

想定ユーザー像：個人投資家（ファンダメンタル分析）、就職・転職検討者、学生・研究者、他ツールからの乗り換え検討者。

| 検索意図 | 検索クエリ例 | 現状の受け皿 |
|---|---|---|
| 企業個社の財務を知りたい | 「〇〇（企業名） 有価証券報告書」「〇〇 ROE」「〇〇 決算 分析」 | `/screener/analyze/:secCode`（弱い） |
| 指標の意味を知りたい | 「ROEとは」「PER 目安」「自己資本比率 業界平均」 | なし |
| 条件で企業を探したい | 「配当利回り 高い 企業」「自己資本比率が高い企業 ランキング」 | なし（機能はあるが固定URLがない） |
| ツールの使い方を知りたい | 「EDINET 使い方」「有報 どこで見る 無料」 | なし |
| ツールを比較検討したい | 「財務スクリーナー 無料」「株探 バフェットコード 比較」 | なし |
| 決算シーズンの情報を知りたい | 「決算発表スケジュール」「今週の有報提出企業」 | なし |

つまり、現状は「企業名 + 分析」という**最も検索されるはずの意図にすら十分応えられておらず**、それ以外の意図（用語・比較・ハウツー）には**入口ページ自体が存在しない**状態。

## 4. コンテンツ企画・構成案

### 4-1. 企業分析ページの SEO 強化（最優先・既存資産の底上げ）

- ページごとに `<title>`・`meta description`・`canonical` を企業名/証券コード/主要指標（売上高・ROE など）を差し込んで動的生成する。
  例）タイトル：「トヨタ自動車（7203）の有価証券報告書・財務分析｜売上高・ROE・PBRを10年分比較 - エディスク」
  ディスクリプション：「トヨタ自動車（証券コード7203）の有報データを無料で分析。売上高◯◯円、ROE◯%、自己資本比率◯%など主要指標を10年分の時系列で確認できます。」
- ページ上部（サマリータブ）に、指標がまだロードされていなくても**企業名・証券コード・直近決算期の主要数値のテキストサマリー文**を先に表示する（SSR/初期HTMLで見える状態にする）。
- 企業単位の構造化データ（`Dataset` または `Article` + `about: Organization`）を追加。
- 企業ごとに動的 OGP 画像（社名・主要指標を焼き込んだ画像）を生成し、SNS シェア時の情報量を増やす。
- パンくず：`トップ > スクリーナー > 業種名 > 企業名` を設置し、業種ページ・用語ページへの内部リンクをフッター的に添える。

### 4-2. 用語集（指標ガイド）セクション — `/glossary/*`

既にアプリ内にある `INDICATOR_KEYS`（ROE・ROA・PER・PBR・自己資本比率・ROIC・Piotroski F-Score・D/Eレシオ・配当性向・EPS・BPS など約 35 指標）をそのまま記事化する。1 指標 = 1 ページ。

各ページの構成テンプレート：
1. 定義（〇〇とは）
2. 計算式
3. 目安・業界平均の考え方
4. 高い/低いと何を意味するか
5. 関連指標へのリンク
6. 「この指標が高い企業を見る」→ `/screener?preset=xxx` への内部リンク（アプリ機能への送客）

用語集は内部リンクのハブとして機能し、企業ページ・ランキングページと相互リンクさせることでサイト全体の回遊性とトピック権威（トピカルオーソリティ）を作る。

### 4-3. ランキング・比較ページ — `/ranking/*`, `/industry/*`

既存のプリセット条件を固定 URL の一覧ページとして公開する。

- `/ranking/roe`（ROEが高い企業ランキング）
- `/ranking/equity-ratio`（自己資本比率が高い企業ランキング）
- `/ranking/dividend-yield`（配当利回りランキング）
- `/ranking/growth`（売上高成長率ランキング）
- `/industry/{業種名}`（業種別の財務指標比較・平均値）

各ページは「上位N社のテーブル＋その指標の解説（用語集ページへのリンク）＋個別企業ページへのリンク」で構成し、検索需要の大きい定番クエリ（「ランキング」系）を面で獲得する。

### 4-4. ガイド・ハウツー記事（ブログ／お役立ちコンテンツ）

ツールを知らない層向けのトップファネル記事。5〜8本程度から着手。

1. 「EDINETとは？有価証券報告書の探し方・読み方」
2. 「有価証券報告書とは？決算短信・四半期報告書との違い」
3. 「個人投資家向け 無料の財務データ・スクリーナー活用法」
4. 「ROE・ROA・ROICの違いをやさしく解説」
5. 「自己資本比率でわかる企業の安全性」
6. 「決算書（BS/PL/CF）の見方入門」
7. 「エディスクの使い方：企業比較からお気に入り登録まで」
8. 「オープンソースの財務データ基盤という選択：エディスクの裏側」（開発者・OSSコミュニティ向け、認知拡散用）

記事末尾から必ず該当する企業ページ・用語ページ・ランキングページへ内部リンクする。

### 4-5. FAQ ページ — `/faq`

「データはどこから？」「更新頻度は？」「無料で使える？」「対応企業数は？」「精度は？」など、既存の README・ENV.md にある情報をユーザー向けに再編集し、`FAQPage` 構造化データを付与。

### 4-6. 更新情報ページ — `/updates`（鮮度・再訪動機）

「直近◯日で新しく提出された有価証券報告書」を一覧化。EDINET 収集パイプライン（`apps/wrapper`）は既に日次取り込みを行っているため、データ加工コストは低い。決算シーズンに合わせた回遊・再訪・SNSでの言及を狙う。

### 4-7. About / 運営者情報ページ — `/about`

データソース（EDINET・公共データ利用規約）、OSSである背景、運営体制、免責事項を明記し、金融データサイトとしての信頼性（E-E-A-T）を補強する。

## 5. 情報設計（サイト構造・内部リンク）

```
トップ
├─ スクリーナー（一覧・フィルタ）
│   └─ 企業分析ページ（証券コード別、数千ページ）
│        ├─→ 用語集（表示している指標へリンク）
│        └─→ 業種ページ（同業種比較へリンク）
├─ ランキング（ROE / 自己資本比率 / 配当利回り / 成長率）
│   └─→ 企業分析ページ／用語集へリンク
├─ 業種別ページ
│   └─→ 企業分析ページ／ランキングへリンク
├─ 用語集（指標ごと、約30〜35ページ）
│   └─→ 該当プリセットのスクリーナー／関連企業へリンク
├─ ガイド／ブログ
│   └─→ 用語集・企業ページへリンク
├─ 更新情報
├─ FAQ
├─ About
├─ お問い合わせ
└─ プライバシーポリシー
```

「企業ページ（実データ・数が多い）」「用語集（意味を説明）」「ランキング（条件で束ねる）」「ブログ（トップファネル）」を相互リンクさせる**ピラー・クラスター構造**にすることで、企業個社の検索だけでなく、指標名・比較・ハウツーの検索も面で獲得できる状態にする。

## 6. 実行優先順位（ロードマップ案）

| フェーズ | 内容 | 狙い |
|---|---|---|
| Phase 1（緊急・技術修正） | canonical をページごとに正しい URL にする／サイトマップに企業ページを全件追加 | 既存の数千ページが正しくインデックス対象になる状態を作る |
| Phase 2（既存ページ強化） | 企業分析ページ・スクリーナー一覧のメタ情報動的化、初期表示のテキストサマリー追加、構造化データ追加 | 検索結果でのクリック率・企業名検索での順位を改善 |
| Phase 3（新規コンテンツ・入口拡張） | 用語集、ランキングページ、業種ページを公開 | 「〇〇とは」「ランキング」系の新規検索流入を獲得 |
| Phase 4（認知・トップファネル） | ガイド記事、About、更新情報、FAQ、SNS用OGP強化 | ツールを知らない層への認知拡大、被リンク・言及の獲得 |

技術修正（Phase 1）が最も投資対効果が高い。既存の数千ページ分の資産が canonical バグとサイトマップ欠如で機能していない状態を先に解消してから、コンテンツ拡充に進むのが合理的。

## 7. 効果測定

- Google Search Console：企業分析ページ・用語集ページ・ランキングページを URL パターンごとにインデックス数/クリック数で分けて追う。
- 主要KPI：インデックス済みページ数（特に `/screener/analyze/*`）、指標名・企業名でのオーガニック流入、`/glossary/*` 経由から `/screener` への内部遷移率。
- Phase 1 実施後、企業ページのインデックス数の変化を最初のチェックポイントとする。
